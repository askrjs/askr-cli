# Qualify generated provider starters

`npm run test:provider-starters` is a coordinated release-consumer check. It requires a separately reviewed complete 18-package `0.5.0` graph, matching normal archive inventories, a running owned candidate registry and a hashed platform/tool admission. It fails when those inputs are absent. Ordinary repository checks and the five default starter checks remain independent.

The caller sets `ASKR_FINAL18_ADMISSION`, `ASKR_FINAL18_ADMISSION_SHA256`, `ASKR_PROVIDER_EVIDENCE` and `ASKR_PROVIDER_PHASE`. Use `native` on Linux/macOS/Windows; the additional Linux `all` phase runs Chromium, Firefox and WebKit. Completion requires 16 native provider/starter cells on each OS and all 48 Linux browser cells. This check does not download browsers or obtain live provider credentials.

Admission also requires a separately reviewed finite-parent witness. It binds the actual caller source/platform/tool, current directory, permitted environment key names and a hash of the complete actual environment; ambient values are never retained. Windows additionally pins its owned `taskkill.exe` termination tool. The unchanged shared process collector inherits that parent when terminating a Windows tree, so finite product-child environments alone are insufficient. Unknown credential/injector/proxy keys, absent witnesses and mismatches fail before children start. Product, compiler, certificate and browser children receive only explicit platform metadata and owned home/config/cache/temp/PATH values.

Each cell uses the physically installed CLI from the admitted normal archive to generate one of Auth0, Microsoft, Google or Apple with SSR, SPA, StartKit or full-stack. The original emitted source, manifest and ranges are retained before ordinary install and fresh `npm ci`. All installed Askr package depths, lock integrity and files must match the candidate archives. Both audits, generated aggregate checks, actual TS6/TS7 with both automatic JSX modes, client/server builds and compiled hosting must pass. SSG remains unsupported.

The independently signed local HTTPS provider verifies state, nonce, PKCE and Apple's client-secret signature. The generated server runs behind an owned TLS front with its configured canonical Host and APP_ORIGIN. A test-only Node preload maps only exact allowlisted provider URLs to pinned-CA HTTPS; it does not replace token validation, provider definitions or application source. Browser traffic uses the same bounded TLS transport and rejects unknown destinations. Successful identity, wrong state/nonce/signature, denial, transaction replay, same-origin logout and private output denial are observed through the compiled generated app. These starters emit identity-only resources; API grant policy is qualified by the Auth and application owners separately.

The relay forwards the browser's actual complete headers, including Cookie and Origin, without synthesizing cookie state. Login uses the generated page's `next` query contract and checks the actual login/callback return target. Protocol events and bounded failure evidence are written before cleanup/protocol success assertions, including failed fixture setup.

The preliminary 13-archive Google origin reproduction is a different fixture projection. It cannot supply final18 admission, original range/dependency acceptance or completion of this matrix. Signed simulation proves the covered protocol/application behavior; live provider compatibility remains a separate boundary.

Raw command logs and failure receipts are retained. Test-owned commands and the compiled server use the shared bounded process owner. Linux browsers have separate BrowserServer PID/start/executable ancestry and shared five-second drain evidence, including explicit inactive zombies and PID reuse. Normal Windows command closure is reported with its existing scope; no Windows browser-tree proof is claimed.
